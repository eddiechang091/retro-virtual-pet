# Retro Virtual Pet 🐣

A browser-based Tamagotchi-style virtual pet game built with React, TypeScript, and Vite. Care for your digital companion as it hatches, grows, and evolves through five unique life stages.

## Features

- **Pet lifecycle** — egg → baby → child → teen → adult (angel or dragon branch)
- **Core care actions** — feed, play mini-games, clean, sleep, heal, and chat
- **Three mini-games** — Guess Direction, Catch Apples, Whack-a-Mole
- **8-bit retro audio** — procedural Web Audio API sound effects (no audio files)
- **Pixel art sprites** — hand-crafted dot-matrix pixel art rendered with SVG
- **Shell color themes** — Classic White, Retro Yellow, Translucent Purple
- **Evolution Dex** — track all unlocked species
- **Persistent state** — pet is saved in `localStorage` with offline decay simulation
- **Keyboard controls** — `A` (Select), `B` (Execute), `C` (Cancel)

## Getting Started

```bash
# Install dependencies
pnpm install

# Start development server
pnpm dev

# Type-check and build for production
pnpm build

# Preview the production build locally
pnpm preview
```

## AI Dialogue (Third-Party LLM via Vercel Proxy)

The pet's dialogue (CHAT) is generated by a third-party LLM through the app's own Vercel serverless proxy (`api/llm.ts`, Groq primary + Cline fallback, same setup as Money Companion's standalone line). **CHAT** asks the model to write one fresh dialogue from the pet's live state — name, species and stage, stats (hunger, happiness, cleanliness, energy, friendship), counters (age, weight, meals, games, dialogues, care mistakes, discipline), and the title of any active random event. The model returns one JSON object: a short opening question (1 sentence, max 140 characters, in character, reacting to how the pet feels right now) plus exactly 2 reply options for the user, each max 10 words, each with the pet's short reaction (max 140 characters). The dialogue plays out exactly like the original canned dialogues — pick one of the two options with [A]/[B], confirm with [B], and the dialogue closes. A new dialogue is generated on every open; there is no free-text input, no continuous conversation, and nothing is stored. When the proxy is unavailable or unconfigured (local dev, plain static hosting, offline), **CHAT** falls back to the existing canned dialogues, exactly as before.

### Where the code lives

| Piece | Location |
|---|---|
| Server-side proxy (Groq primary, Cline fallback, per-IP rate limit) | `api/llm.ts` |
| Vercel output directory | `vercel.json` |
| LLM client (`getLlmService`, `LlmUnavailableError`, `LlmProxyNotConfiguredError`) | `src/services/platform/llm.ts` |
| Pet dialogue: prompt builder, cleaner, option guard, parser | `src/services/platform/chat.ts` |
| Dialogue UI (loading placeholder in `dialogue` mode) | `src/game/components/LcdScreen.tsx` |
| Chat wiring (generation, fallback, late-result guard) | `src/App.tsx` |
| Tests | `src/services/platform/__tests__/chat.test.ts`, `src/services/platform/__tests__/llm.test.ts` |

Picking an option grants mood +10, happiness +8, and `totalDialogues` +1, same as the canned dialogues. If the model returns invalid JSON, no question, or fewer than 2 usable options, the app falls back to a canned dialogue. While a dialogue is generating, the LCD shows a small "thinking…" placeholder; pressing [C]/[Esc] cancels it.

### Setup (Vercel)

```bash
pnpm build   # tsc + vite -> bundle/ (app.js, styles.css, index.html)
```

1. Import the repo into Vercel (the `vercel.json` already points the output at `bundle/`).
2. In the Vercel project settings, set `GROQ_API_KEY` (required — get one at https://console.groq.com/keys, free tier, no card) and optionally `CLINE_API_KEY` (fallback — get one at https://app.cline.bot, free tier). Optional overrides: `GROQ_MODELS` / `CLINE_MODELS` (comma-separated, tried in order).
3. Deploy. The keys stay server-side in the proxy — the browser never sees them.

Without deployment, or without keys set, the app still works: **CHAT** just uses the canned dialogues. To test the proxy locally, run `vercel dev` (Vercel CLI) instead of `pnpm dev`.

> History: the app previously integrated Anna LLM (PR #1 / #2 era). That integration was removed; dialogue now runs through the app's own proxy instead.

> Note: `index.html` references `/favicon.png`, but no favicon file exists in the repo, so no favicon is shipped in `bundle/` and the request 404s when served statically (harmless — the browser just shows no icon). To add one, drop a `favicon.png` in `public/` and it will be copied into `bundle/` at build time.
